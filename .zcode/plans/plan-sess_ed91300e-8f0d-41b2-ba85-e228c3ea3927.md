# Kế hoạch rút gọn OpenKey — bản Windows thuần, Telex + VNI, UI mới

## Bối cảnh
OpenKey hiện là bộ gõ đa nền tảng: engine C++ dùng chung (~3.500 dòng: `Sources/OpenKey/engine/`) + 3 shell: macOS (~5.600 dòng), win32 (~4.640 dòng), Linux (stub). Bạn cần: **bỏ macOS + Linux**, **chỉ giữ 2 kiểu gõ Telex + VNI**, **bỏ tính năng thừa**, **tối ưu hiệu năng**, và **làm mới giao diện** — chạy ổn trên Win10/11.

Vì bạn không chọn trong câu hỏi trước, tôi áp dụng phương án đề xuất (có thể đổi khi review plan):
- **Chỉ giữ bảng mã Unicode** (bỏ TCVN3, VNI Windows, Unicode Tổ hợp, CP1258) → bỏ luôn Công cụ chuyển mã.
- **Giữ**: Macro (gõ tắt), Smart Switch (nhớ VI/EN theo app), Quick Telex + phụ âm tắt, kiểm tra chính tả, chính tả hiện đại (oà/uý), phục hồi từ sai, viết hoa đầu câu, tạm tắt bằng Ctrl/Alt, phím tắt đổi VI/EN, fix autocomplete trình duyệt.
- **Bỏ**: Simple Telex 1/2, ConvertTool, tự động cập nhật (OpenKeyUpdate.exe), nhớ bảng mã theo app, vOtherLanguage, vFreeMark (đã chết), hỗ trợ Metro/UWP (hack HWND_BROADCAST), fix Chromium beta (hack Shift+Left).
- **Giao diện**: Dark hiện đại kiểu Win11 (bo góc, accent xanh, toggle switch), tự động graceful trên Win10.

## Bước 2 — Rút gọn engine
- **`engine/DataType.h`**: `vKeyInputType` còn `{vTelex, vVNI}`; đơn giản hoá `IS_SPECIALKEY`, `IS_MARK_KEY` (bỏ nhánh Simple Telex, `DataType.h:133-146`); xoá `IS_DOUBLE_CODE`/`IS_VNI_CODE` (chỉ dùng cho bảng mã 2-byte); bỏ giá trị `vBreakWord` trong `HoolCodeState` (engine không bao giờ gán).
- **`engine/Vietnamese.cpp`**: gộp `_codeTable[5]` thành 1 bảng Unicode duy nhất, đổi thành **mảng index trực tiếp thay `std::map`** (hiện `getCharacterCode` `Engine.cpp:501-558` gọi 2 lần `map::find` cho mỗi ký tự xuất ra — thắng lớn nhất của hot path); xoá `douKey` (chết), `_unicodeCompoundMark`.
- **`engine/Engine.cpp`**:
  - Bỏ nhánh Simple Telex: dòng 3-4 bảng `ProcessingChar` (`:34-39`), điều kiện `vSimpleTelex1` tại `:1187`, `:1541`.
  - `getCharacterCode` → lookup mảng O(1) 1 bảng.
  - Bỏ gate `vFreeMark` (`:1504`), xoá vestige `isRestoredW`, bỏ mọi đường gọi ConvertTool.
  - *(Cẩn trọng, riêng biệt)*: sửa 3 điều kiện vô lý trong `handleModernMark` (`:672-674`, `:688-691` so sánh cùng 1 index với 2 chữ khác nhau — chắc chắn ý là `VSI+1`). Ảnh hưởng hành vi → kiểm thử kỹ bằng gõ thực tế; nếu có sai lệch thì bỏ mục này.
- **`engine/Macro.cpp`**: `findMacro` trả `const MacroData*` thay vì copy cả struct mỗi lần trúng (`:161-178`); giữ nguyên định dạng import/export UniKey.
- **`engine/SmartSwitchKey.cpp`**: giữ; giá trị lưu chỉ còn ngôn ngữ (bỏ phần bảng mã).
- Xoá `engine/ConvertTool.cpp/.h`. Dọn `engine/Engine.h` (bỏ extern của tính năng đã bỏ).

## Bước 4 — Giao diện mới (dark Win11-style, giữ Win32 thuần — không thêm dependency)
- **`OpenKey.rc` + `resource.h`**: dọn dialog đã bỏ, sắp lại layout các dialog còn lại (MAIN + 3 tab, MACRO, ABOUT).
- **Theme engine nhỏ** (file mới `UITheme.cpp/h` hoặc trong `BaseDialog`): palette dark (#202020 nền, #2B2B2B panel, accent #4CC2FF kiểu Win11), font Segoe UI 9pt.
- **DWM**: title bar tối (`DWMWA_USE_IMMERSIVE_DARK_MODE` 20, fallback 19 cho Win10 cũ), bo góc Win11 (`DWMWA_WINDOW_CORNER_PREFERENCE`) — tự no-op trên Win10.
- **Custom draw**: checkbox → **toggle switch** vẽ tay (WM_DRAWITEM); tab vẽ lại kiểu pill/clean; nút OK/Exit/Default vẽ accent; nền dialog tự paint (bỏ màu xám hệ thống); ComboBox giữ nguyên hệ thống (chấp nhận được trên dark).
- Áp cùng theme cho `MacroDialog` (ListView dark) và `AboutDialog` (bỏ nút cập nhật).
- Tray icon giữ nguyên bộ icon hiện có.

## Bước 5 — Build & kiểm thử
- Build bằng VS2022 Build Tools có sẵn trên máy:
  ```
  "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe" Sources\OpenKey\win32\OpenKey\OpenKey.sln -m -t:Rebuild -p:Configuration=Release -p:Platform=x64
  ```
  (lặp với `-p:Platform=x86`) — cả 2 config phải build sạch 0 error.
- Chạy `OpenKey64.exe`, kiểm thử thủ công trong Notepad/Brave:
  1. Telex: `aa`→â, `dd`→đ, `oanw`→oàn; VNI: `a1`→à, `9`→ơ, `0`→đ.
  2. Chính tả hiện đại: `oa`+dấu → `oà` (bật/tắt toggle so sánh `òa`).
  3. Từ sai → phục hồi phím gốc khi bật "Phục hồi phím".
  4. Macro: thêm `dc`→`được`, gõ ra đúng, import/export file txt.
  5. Smart Switch: gõ VI ở app A, chuyển app B tự về EN, quay lại A tự về VI.
  6. Phím tắt Alt+Z đổi VI/EN; double-tap Ctrl tạm tắt chính tả; double-tap Alt tạm tắt engine.
  7. Tray menu: đổi kiểu gõ, bật/tắt tính năng; settings tồn tại sau restart (registry).
  8. Giao diện: dark theme đúng ở cả Win11 (bo góc, title bar tối) — không crash trên Win10.
- Chỉnh UI chỉn chu thêm 1 vòng screenshot sau khi test chức năng.

## Kết quả kỳ vọng
- Engine ~3.500 → ~2.500 dòng; app win32 ~4.600 → ~3.000 dòng; bỏ 2 project con (OpenKeyUpdate) và toàn bộ macOS/Linux.
- Hot path nhanh hơn rõ rệt: lookup bảng mã O(1) thay `std::map`, không copy MacroData, không sổ `_syncKey`, ít phân bổ heap mỗi phím.
- Repo & UI: chỉ còn 1 solution Windows, giao diện dark hiện đại đồng nhất, cài đặt cũ trong registry vô hại (key thừa bị bỏ qua).
